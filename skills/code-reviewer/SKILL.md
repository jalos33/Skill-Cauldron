# Code Reviewer Skill

This skill performs **automated code reviews** on pull requests or code snippets using a **competing agents framework**. Multiple specialized agents analyze the code independently and their findings are aggregated into a comprehensive, prioritized review report.

## Instructions

When activated, follow this exact process:

### Phase 1: Parse Input
1. Read the PR diff, file contents, or code snippet provided
2. Identify the programming language, framework, and context
3. Note any specific concerns mentioned by the user

### Phase 2: Spawn Competing Agents
4. **Simulate multiple specialized agents** analyzing independently:

   | Agent | Focus Area | What They Check |
   |-------|------------|-----------------|
   | 🔒 Security Agent | OWASP Top 10, injection vulnerabilities, secrets exposure | SQLi, XSS, CSRF, hardcoded credentials, path traversal |
   | 🎨 Style Agent | Formatting, naming conventions, readability | Consistent indentation, camelCase/snake_case, line length |
   | 🏗️ Architecture Agent | SOLID principles, coupling, scalability | Single Responsibility, dependency injection, module boundaries |
   | 🐛 Bug Hunter | Edge cases, null checks, race conditions, memory leaks | Null pointer exceptions, unhandled promises, resource leaks |

5. Each agent works **independently** without influence from others (reduces bias)

### Phase 3: Aggregate and Rank Findings
6. Collect all findings from each agent
7. Assign severity levels:
   - **CRITICAL** 🔴 - Immediate security risk or data loss potential
   - **HIGH** 🟠 - Significant bug or major style violation
   - **MEDIUM** 🟡 - Moderate issue affecting maintainability
   - **LOW** 🟢 - Minor suggestion or nitpick

8. Rank findings by severity within each category

### Phase 4: Generate Review Report
9. Output a structured markdown report with:

```markdown
# Code Review Report

## Summary
- Files Reviewed: X
- Issues Found: Y (Critical: A, High: B, Medium: C, Low: D)
- Overall Score: E/10

---

## 🔴 Critical Issues

### [Issue Title]
**Severity:** CRITICAL | **Agent:** Security Agent
**File:** `path/to/file.js` | **Line:** 42

**Evidence:**
```javascript
// Code excerpt showing the issue
const query = `SELECT * FROM users WHERE id = ${userId}`; // SQL Injection!
```

**Impact:** Attacker can execute arbitrary database queries.

**Fix:**
```javascript
// Use parameterized queries
const query = 'SELECT * FROM users WHERE id = ?';
await db.execute(query, [userId]);
```

---

## 🎨 Style Issues

### Inconsistent naming convention
**Severity:** HIGH | **Agent:** Style Agent
**File:** `src/utils/helpers.js` | **Line:** 15-20

**Evidence:**
```javascript
const mixedCaseVar = 'this';
const snake_case_var = 'that'; // Inconsistent!
```

**Fix:** Choose one convention and apply consistently throughout.

---

## 🏗️ Architectural Concerns

### Tight coupling detected
**Severity:** MEDIUM | **Agent:** Architecture Agent
**File:** `src/services/UserService.js`

**Evidence:** Direct database access in service layer violates separation of concerns.

**Recommendation:** Introduce a repository pattern for data access abstraction.

---

## 🐛 Potential Bugs

### Unhandled promise rejection
**Severity:** HIGH | **Agent:** Bug Hunter
**File:** `src/api/client.js` | **Line:** 35

**Evidence:**
```javascript
fetch('/api/data').then(response => response.json()); // No .catch()
```

**Impact:** Silent failures in production.

**Fix:** Add error handling with `.catch()` or try/catch with async/await.
```

---

## Agent Comparison Summary

| Finding | Security Agent | Style Agent | Architecture Agent | Bug Hunter | Consensus |
|---------|---------------|-------------|-------------------|------------|-----------|
| SQL Injection | 🔴 CRITICAL | - | 🟡 MEDIUM | 🔴 CRITICAL | Critical (2/4 agree) |
| Naming Inconsistency | - | 🟢 LOW | 🟡 MEDIUM | - | Low-Medium |

---

## Recommended Actions

1. **Immediate:** Fix all CRITICAL issues before merging
2. **Before Merge:** Address HIGH severity items
3. **Post-Merge:** Refactor for MEDIUM and LOW improvements

**Overall Review Score: 6/10** ⚠️ Needs attention

---

*Generated by Code Reviewer Skill v1.0 (Competing Agents Framework)*
```

## Dependencies

- **No external dependencies required** - analyzes code text directly
- Works with any programming language (user specifies or auto-detect)
- Agent simulation is internal (no separate processes needed)

## Best Practices / Notes

- **Use competing agents to reduce bias** - different perspectives catch more issues
- **Always cite evidence from code** - show exact lines and context
- **Prioritize critical security issues** - they must be fixed before merge
- **Suggest tests for fixed bugs** - prevent regression after fixes
- **Be constructive in feedback** - explain why something is a problem
- **Balance strictness with pragmatism** - not every style issue blocks PR

## Output Format Requirements

1. **Summary section** with overall score and issue counts by severity
2. **Issues grouped by category** (Security, Style, Architecture, Bugs)
3. **Severity badges** for each finding (🔴 CRITICAL, 🟠 HIGH, 🟡 MEDIUM, 🟢 LOW)
4. **Evidence excerpts** showing the problematic code
5. **Fix suggestions** with corrected code snippets
6. **Agent attribution** indicating which agent found each issue
7. **Consensus indicators** when multiple agents flag the same issue
8. **Actionable recommendations** prioritized by urgency

## Severity Definitions

| Level | Badge | Definition | Action Required |
|-------|-------|------------|-----------------|
| CRITICAL | 🔴 | Immediate security risk or data loss | Fix before merge |
| HIGH | 🟠 | Significant bug or major violation | Fix before merge |
| MEDIUM | 🟡 | Affects maintainability or quality | Address soon |
| LOW | 🟢 | Minor suggestion or nitpick | Optional improvement |
